# Sidefolk v1: the release contract

**Status:** binding. Ruled by the supreme council on 25 October 2026
([ruling](audit-2026-10-25-claude/supreme/RULING.md)), after two independent eight-seat audits
([Claude](audit-2026-10-25-claude/COUNCIL-REPORT.md), [Codex](audit-2026-10-25/COUNCIL-REPORT.md),
[comparison](audit-2026-10-25-claude/ADDENDUM-COMPARISON.md)). The founder told the agents to
start implementing it on 25 October 2026.

This document replaces [PLAN-V2.md](PLAN-V2.md) sections 6–10 and [ROADMAP.md](ROADMAP.md) as
the plan. Every requirement has an ID. Agents cite IDs in commits, STATUS and checks. Nothing is
added without the change process in §13. The founder can veto any item in §15 in writing.

## 1. Promise and audience

**V1-P1. Promise.**
> Pip sits on your desktop, taps you when Claude Code or a reminder needs you, takes you to that
> exact session, and keeps a dated log of what you got done.

**V1-P2. Audience.** Mac developers who run Claude Code (Codex as a beta), and want their own
reminders and a work log in the same place.

**V1-P3. Two tracks.**

| Track | Contents | What it gates |
|---|---|---|
| Core track | Reminders, work log, Quick add, one Pip, release basics | Required for v1 |
| Agent track | Claude Code status, requests on Pip, Open session | Required for the word "stable" on those features |

If the agent track fails its native gate (G2-agent, §12) one week after its phase ends, v1 ships
anyway, with:
- Sessions labelled Beta;
- no approvals from Pip;
- the promise without its session clause.

**V1-P4. Calm path.** Setup offers "Skip, I don't use AI tools". After that the app shows Today,
Reminders and Work log, and no developer vocabulary anywhere. Setup and Quick add show no
session, hook, terminal, MCP or command words.

**V1-P5. Widening gate.** Sidefolk is marketed to everyday users only when both of these hold:
- ≥30% of weekly beta actives use reminders or the log with no agent connected, for two weeks
  running;
- the Apple Reminders export (v1.1) has shipped.

**V1-P6. Not v1.** A general AI assistant, a task manager, a coding environment, a terminal,
watching every possible agent, Windows.

## 3. Data and storage (applies to every store)

- **V1-S1.** Every JSON store (settings, companion, reminders, journal index) is wrapped as
  `{ "version": n, "data": … }`, and migrations are tested with fixtures.
- **V1-S2.** Each load ends in one of three states: **Missing** (start empty), **Ok**, or
  **Corrupt**.
  - A Corrupt file is renamed to `<name>.corrupt-<timestamp>` and never overwritten.
  - The app starts with defaults and shows: "I couldn't read your reminders file. Your data is
    safe · Restore last good copy".
- **V1-S3.** After every Ok load, the bytes are copied to `<name>.bak`. "Restore last good copy"
  uses it.
- **V1-S4.** Writes are atomic: temp file, then fsync, then rename. A failed write shows an error
  in the voice table (§8.4), and the in-memory state is kept.
- **V1-S5.** Damaged data is never shown as empty ("No reminders yet"). Lists show loading,
  error, stale and empty as separate states.
- **V1-S6.** Settings never block launch. A corrupt settings file is quarantined, defaults load,
  and a banner explains what happened.
- **V1-S7.** Notes stay plain Markdown files: one file per notebook, hand-written lines kept.
- **V1-S8.** The journal keeps **7 days** by default and stores only the first prompt line.
  - It can be switched off.
  - Settings has a Clear button.
  - Commands and tool inputs are never written to the journal.

## 4. Reminders contract

- **V1-R1. Kinds.** A one-off, or a repeating alert that works like a calendar repeat.
  "Repeat after I finish" is LATER.
- **V1-R2. Series vs occurrence.**
  - A series stores its rule plus a wall-clock anchor: floating local time, or an IANA zone if
    the user picked one.
  - Occurrences are computed from the series.
  - Overrides (snooze, skip, done) are stored per occurrence.
  - The engine lives in Rust (`reminders.rs`). `src/reminders.ts` only renders.
- **V1-R3. Rules supported.**
  - Daily; weekdays; weekly on one or more weekdays ("Monday and Thursday").
  - Every N days or weeks (1–52).
  - Monthly by date ("every month on the 31st" fires on the last day of shorter months).
  - Yearly.
- **V1-R4. Firing.**
  - Every occurrence fires on schedule, whether or not the last one was handled.
  - **Done** completes that occurrence.
  - **Skip next** exists.
  - Editing a series asks "This one / All future".
- **V1-R5. Snooze.**
  - Choices: 10 min, 1 hour, This evening (18:00), Tomorrow 9:00, Pick…
  - A snooze moves one occurrence. **The anchor never moves**: a Monday weekly reminder snoozed to
    Tuesday still fires the next Monday.
  - The default snooze is set in Settings → General.
- **V1-R6. Unhandled reminders.**
  - **A one-off stays Overdue on Today until handled. It is never auto-hidden.**
  - A repeat occurrence goes into history as *missed* only when the next occurrence fires.
  - One sound and one card per firing. After 2 minutes the card folds, and Pip keeps holding the
    note with a count badge. No re-nag.
- **V1-R7. Quit and sleep.**
  - macOS notifications are pre-scheduled on every change, in this order:
    1. all one-offs;
    2. the next occurrence of each series;
    3. further occurrences, round-robin, up to **60 pending** (macOS limit 64).
  - Clicking a notification opens the reminder's details.
- **V1-R8. Late.** On launch or wake, Pip shows one card: "While you were away: N reminders".
  - Each reminder shows its original time and a *late* tag.
  - Only the latest missed occurrence per series is shown.
- **V1-R9. Start at login** is on by default, turned on in setup with the result shown.
- **V1-R10. Notifications denied.** Setup and the reminder editor say: "Reminders show only while
  Sidefolk is running."
- **V1-R11. Daylight saving.**
  - A time that doesn't exist (spring forward) fires at the next valid minute.
  - A time that exists twice (fall back) fires once, the first time.
  - Changing the Mac's time zone moves floating reminders with it.
- **V1-R12. Phone reach.** None in v1. The editor and setup say "Reminders appear on this Mac."
  v1.1 adds "Also add to Apple Reminders" (write-only).
- **V1-R13. Agent-aware reminders.**
  - "remind me when api finishes" fires on that project's next *done* event.
  - It expires after 24 hours with a note.
  - It ships with the agent track.
- **V1-R14. Editor.**
  - Date and time fields always hold real values. The default is today, or tomorrow if the time
    has already passed. A placeholder never stands in for a value.
  - The time zone is shown.
  - The resolved date is shown before saving.
- **V1-R15. Today** shows, in this order: Overdue, Needs you, Today's reminders, Running sessions,
  Recent log.

## 5. Work log contract

- **V1-L1. Name and shape.**
  - The sidebar item is **Work log**.
  - It holds a default notebook, **Log** (the inbox), plus topic notebooks the user creates.
- **V1-L2. Capture.** "note: …" and "log …" go to Log, with no question asked.
- **V1-L3. Named notebook.** "note for X: …" needs an exact name or alias match
  (case-insensitive). Otherwise:

  | Matches | Pip offers |
  |---|---|
  | one near match | "Add to *Evaluation H2 2026*?" |
  | several | a choice list |
  | none | "New notebook 'X'" or Log |

  The draft is never lost while the user chooses. The old "most recently updated wins" rule is
  deleted.
- **V1-L4. Visible destination.**
  - The preview shows the destination before saving.
  - After saving: "Noted in X · Move · Undo". Undo stays until dismissed, and ⌘Z works.
  - Every entry has Move.
- **V1-L5. Timeline.**
  - "All entries" is one dated stream, grouped by week.
  - It can be filtered by notebook and project.
- **V1-L6. Search** matches text and dates: "October", "last week", "2026-04".
- **V1-L7. Log it (agent work).**
  - A finished Claude Code session offers **Log it** on its done card and on its session row.
  - The entry is prefilled as `<project>: <first prompt line>` and is editable.
  - Only that text is stored. Nothing is ever written automatically.
- **V1-L8. Your week.**
  - At Friday 16:00 (configurable or off), Pip holds up "Your week: N entries".
  - The view lists that week's entries plus completed reminders, with Copy as Markdown.
  - No AI in v1.
- **V1-L9. Export.**
  - Copy as Markdown per notebook, per week, and for everything.
  - Show in Finder.

## 6. Quick add (the input)

- **V1-Q1. One engine.**
  - `src/commands.ts` + `src/when.ts`, pure TypeScript, shared by the companion and the window.
  - The field is labelled **Quick add**, placeholder "Remind me…, note…, open…".
  - **A task finishes on the surface where it started.**
- **V1-Q2. Precedence, first match wins:**
  1. **Card answers**, while a card has focus: "allow", "decline", "snooze".
  2. **`$ …`**. If Labs → Quick actions is on, it shows a terminal preview. If it's off: "Commands
     are off. Turn on in Settings → Labs". There is **no `run …` prefix**.
  3. **App and session verbs:** "what's today", "show notes", "notes", "reminders", "sessions",
     "open api session", "continue docs", "undo", "help", "hide", "rename to X".
  4. **Notes:** `note[ for X]: …`, `log …` (§5).
  5. **Any resolvable date or time** makes a reminder draft. This runs **before** `open`, so "open
     enrollment closes friday 5pm" becomes a reminder.
  6. **`open …`:** an app, a folder or an https URL, after a preview.
  7. **About 20 small-talk replies in Pip's voice,** each with a pose (hi, thanks, good morning…).
  8. **Everything else** becomes a Log note draft, with "Make it a reminder… / Discard".
     - Never "I don't know".
     - **English never becomes a shell command.**
- **V1-Q3. Times.**

  | Words | Time |
  |---|---|
  | a bare hour ("at 3") | the soonest future of 3:00 or 15:00 that falls between 07:00 and 21:59 |
  | tonight | 20:00 |
  | this evening | 18:00 |
  | end of day | 17:00 |
  | morning | 09:00 |
  | afternoon | 15:00 |
  | noon | 12:00 |

  Chrono's full results are used, so "standup 9:30" keeps 9:30.

  A repeat keeps working hours instead: 1–7 means the afternoon, so "every weekday at 9" stays at
  09:00 (DECISIONS #40). A reminder with only a date, whose 09:00 has already passed, asks when
  instead of saving a time in the past.
- **V1-Q4. Compound schedules.** Weekday lists are supported ("Monday and Thursday"). Anything
  unsupported gets a question. Nothing is partially accepted.
- **V1-Q5. Preview.**
  - The resolved date and time always show before saving.
  - Unambiguous input saves on Enter, then shows Undo.
  - Ambiguous input shows inline choices ("3 PM today · 3 AM tomorrow").
- **V1-Q6. No model in v1.** v1.1 may add Apple's on-device model, only to propose a structured
  draft for the step-8 bucket, always with a confirmation.
- **V1-Q7. Corpus.** 300 phrases in `npm test`:

  | Group | Phrases |
  |---|---|
  | everyday | 150 |
  | developer | 100 |
  | adversarial | 50 |

  - Run on a fixed clock, in two time zones (Europe/Paris, Asia/Tokyo), across DST dates.
  - Gates:
    - ≥95% correct intent and time;
    - **100%**: no shell offered without `$`;
    - **0** reminders saved without a visible resolved time;
    - **0** silently wrong times.
  - Every miss found in the beta becomes a corpus line.

## 7. Developer contract

### 7.1 Tools

- **V1-D1. Claude Code** (stable, agent track): hooks, requests on Pip, MCP.
- **V1-D2. Codex** (beta).
  - Status, plus the MCP tools `notify`, `ask` and `remind`.
  - **Pip never answers Codex approvals.** The card reads "Codex needs you in api · Open".
  - A 2-day spike finds Codex's documented signals: the `notify` program, plus any hook
    mechanism.
  - **Undocumented rollout-file parsing is forbidden.**
  - Fallback if the spike finds nothing better: "turn finished" via `notify` only, with no
    "needs you" claim.

### 7.2 Host capability matrix

Shown word for word in Settings → Agents.

| Host | Open | "That session is focused" | Spike → result |
|---|---|---|---|
| Terminal.app | Exact tab (tty) | Exact: frontmost and the selected tab's tty | — |
| iTerm2 | Exact tab (tty) | Exact | — |
| Ghostty 1.3+ | Bring forward + "select the session there" | Only if frontmost **and** it hosts exactly one live Claude session | 1 day: tty/cwd via AppleScript → exact |
| WezTerm | Bring forward | As Ghostty (add to the host list) | 0.5 day: `wezterm cli` → exact |
| VS Code / Cursor | Bring that project's window forward, else the app | As Ghostty | 0.5 day |
| Warp | Bring forward | Never | — |
| Claude desktop | Bring forward | Never | — |
| tmux / ssh / unknown | "Running in tmux on ttys004 · Copy attach command" | Never | exact in v1.1 |
| Ended session | `claude --resume <id>` in the default terminal | — | — |

**V1-D3.** A live process is **never** resumed a second time.

### 7.3 Requests

- **V1-D4. Routing.**
  - Pip holds a request unless *that session* is focused, judged by the matrix. If focus is
    unknown, the request shows on Pip.
  - If the user focuses that session while the card is open, Pip **releases within 1 s** to
    Claude's own prompt. The card becomes "Moved to your terminal · Open".
- **V1-D5. Hold.**
  - **60 s** (today's `PERMISSION_WAIT`), under the installed 90 s hook timeout.
  - The card says "Claude waits about a minute, then asks in your terminal".
  - On expiry the request is released, never allowed or declined.
  - A released or expired request can never become an Allow; `requests.rs` enforces this.
- **V1-D6. Raw operation.**
  - Rust keeps the raw, immutable tool input, and the display is derived from it.
  - Commands are shown byte-exact: whitespace kept, control and bidi characters as visible
    escapes.
  - Edit shows the real diff, from `old_string`/`new_string`.
  - Write shows the full content.
  - MCP calls show pretty-printed JSON.
- **V1-D7. Allow only when seen.**
  - Anything larger than the card opens a full view, and **Allow appears only once the whole
    operation has been shown.**
  - An operation that can't be shown offers only "Answer in terminal" and Open.
- **V1-D8. Buttons.** Allow once · Decline · Answer in terminal. There is no "always" and no
  "allow everything".
- **V1-D9. Risk.**
  - Risk labels are warnings only, never policy.
  - On a flagged command, Decline is the default button.
- **V1-D10. No auto-answer.**
  - Sidefolk never answers on its own.
  - Start session (beta) offers Claude's own permission modes, each named in Claude's terms. The
    session row shows the mode as a read-only badge.
- **V1-D11. Identity.**
  - A session is labelled project + first prompt line + host.
  - Clicking Pip opens a compact session list: "api · needs you / web · working / docs · done".
  - Done and failed events queue behind an open request and are never dropped.
- **V1-D12. If Sidefolk isn't running or was deleted,** Claude Code behaves exactly as it would
  without Sidefolk installed (§10, sidecar).
- **V1-D13. Health.** The Claude Code connection shows exactly one state: Not connected,
  Connected and waiting for the first session, Working, Needs repair (with the reason and a Repair
  button), or Port or socket unavailable.
- **V1-D14. Queue.** At most 5 open requests per session; the card shows "+N more".

## 10. Security, privacy, distribution

- **V1-X1. Hook transport.**
  - The nine HTTP hooks are replaced by **command hooks** that call a small signed sidecar,
    `sidefolk-hook` (Tauri `externalBin`).
  - The sidecar forwards stdin over a **Unix socket in the 0700 data folder**, and checks that
    the peer has the same uid.
  - The installed line is a guarded wrapper: `test -x <sidecar> && exec <sidecar> hook || exit 0`.
  - If the app isn't running or is gone, events exit 0, and PermissionRequest returns no
    decision, so Claude asks normally.
  - No other process can take over the socket.
- **V1-X2. Uninstall.**
  - "Disconnect & uninstall…" is in Settings → Privacy & data and in the menu bar.
  - It removes only our hook and MCP entries (with backups), the login item, and any CLI link.
  - Data is kept by default. The user can choose "Export first" or "Delete data".
  - `sidefolk-hook uninstall` works even after the app has been moved to the Bin.
- **V1-X3. Installers.**
  - They refuse to run from a translocated app.
  - They back up configs byte for byte.
  - Config changes go only through the agents' own CLIs or our marked entries.
- **V1-X4. Signing.**
  - Developer ID, hardened runtime.
  - `notarytool` with a keychain profile or API key; never a password in the environment.
  - The DMG is stapled.
- **V1-X5. Entitlements.**
  - `com.apple.security.automation.apple-events`, plus `NSAppleEventsUsageDescription`.
  - No calendar entitlement until v1.1. No App Sandbox.
- **V1-X6. Updater.**
  - `tauri-plugin-updater`, with a signed `latest.json` on GitHub Releases.
  - Updates install only with consent, and show release notes in Pip's voice.
  - The feed carries `min_safe_version`. Below it, Pip stops holding requests: the kill switch.
- **V1-X7. Pause answers** in the menu bar: Pip stops holding requests until resumed.
- **V1-X8. Recording protection.** A 0.5-day spike: the founder checks Mission Control with the
  protection on, now that the overlay only covers the companions.
  - Acceptable: the default is **on**.
  - Not acceptable: off, and setup offers "Hide Pip's cards from screen shares?".
- **V1-X9. Platform.**
  - macOS 14+, Apple Silicon only. Bundle metadata must say 14.0.
  - Intel only once someone can test it.
- **V1-X10. Crashes.**
  - A local crash log, plus dSYMs archived per release. No network upload.
  - `eprintln` output goes to the log file.
- **V1-X11. Privacy page in the app,** one screen:
  - what stays local;
  - what the journal keeps (first prompt line, 7 days);
  - when data leaves (only a "uses Claude" action the user clicks).
- **V1-X12. Copy report** shows a preview first and redacts paths under home, tokens and names.
- **V1-X13. License.**
  - Code: MIT.
  - Pip's art, name and logo: all rights reserved.
  - Free. Channel: notarized DMG on GitHub Releases, then a Homebrew cask.
  - Not the Mac App Store.
- **V1-X14. Outside users.** None enables approvals until all four of these ship:
  - the fail-closed sidecar (X1);
  - uninstall (X2);
  - the signed updater (X6);
  - the kill switch (X6).
- **V1-X15. Single instance.** A second launch focuses the first. A failed socket or port bind
  shows in the UI.
- **V1-X16. Webview commands** are scoped per window: the overlay can't call window-only
  commands, and the reverse.

## 11. Architecture

Keep Tauri 2, Rust, TypeScript and the frame renderer. **Rust owns all domain state.** The two
webviews (overlay, window) subscribe to typed events and invoke commands. Reloading a webview
loses nothing.

| Module | v1 |
|---|---|
| `store.rs` (new) | Versioned envelope; Missing / Ok / Corrupt; quarantine; `.bak`; atomic writes; migrations |
| `requests.rs` (new) | Request lifecycle: pending → answered / released / expired; raw operation; display; per-session cap |
| `hooks.rs` | Lifecycle moved out; routing per V1-D4; clipping only for display |
| `bus.rs`, `prefs.rs` | Typed events and state; no 1 s / 3 s polling; config files watched by mtime |
| `reminders.rs`, `notifications.rs` | Series engine (§4), pre-scheduling |
| `notes.rs`, `src/notes.ts` | Log/inbox, exact-or-ask, timeline index, export; draft summary removed |
| `settings.rs` | Quarantine on corrupt input; never `expect` at launch |
| `sessions.rs` | No double resume, first-prompt names, host matrix |
| `claude_setup.rs`, `mcp_setup.rs` | Sidecar hooks, uninstall, health; refuse when translocated |
| `mcp.rs` | Keep; drop `spark`; `ask` gains identity and a deadline |
| `journal.rs` | First line only, 7 days, off switch, Clear |
| `actions.rs` | Trimmed to `run_in_terminal` and `open` |
| `crew.rs` | Replaced by typed companion settings in `store.rs` |
| `panel.rs`, `overlay.rs`, `tray.rs`, `app_menu.rs` | Keep; tray gains Pause answers and Uninstall |
| `main.rs` | Single instance, bind health in the UI, async IO commands |
| `codex.rs`, `inside.rs`, `characters.rs`, `voice.rs` | Delete |
| `calendar.rs`, `src/calendar.ts` | Keep behind the `calendar` feature, off |
| `src/access.ts`, `src/dashboard/terminal.ts`, `src/character-import.ts`, `src/dashboard/characters.ts`, `src/workers.ts`, `src/roster.ts` (crew parts) | Delete |
| `src/companion.ts`, `src/agents.ts` | Render Rust state; hold none |
| `src/commands.ts`, `src/when.ts` | §6 grammar and corpus |
| `src/dashboard/*` | Views re-implemented (§9) after P1 |

**Error handling.** IO and parse errors become UI states; there is no `unwrap` on IO or parsing.
`lock().unwrap()` may stay, because under `panic = "abort"` the process dies before a lock can be
poisoned.

**Tests to add:**
1. The hook flow in-process: allow, decline, release on focus, expiry, app not running, and "a
   long prefix can't change the outcome".
2. Corrupt, unreadable and disk-full cases for each store.
3. Recurrence on fixed clocks, in two zones: DST, month ends, snooze, skip.
4. The 300-phrase corpus.
5. An install → uninstall round trip on temporary `CLAUDE_CONFIG_DIR` / `CODEX_HOME`, restored
   byte for byte.
6. An overlay reload with an open request (WebKit).
7. The voice-table string check.
8. A release script that fails closed when any check is missing.

## 12. Release gates, beta, decision rules

Each gate is recorded in `docs/checks/<gate>.md`: date, build hash, and pass/fail per line,
recorded by the founder on a signed build in a clean macOS user account. Agents never mark a gate
passed.

| Gate | Passes when |
|---|---|
| **G1 Trust** | B1, B2, B5, B9 and Codex F01–F03, F05, F06 are closed, each with a regression test; no code path auto-answers; 0 wrong-session approvals in a 3-session, 3-host test |
| **G2-core** | Reminders while visible, hidden, window closed, quit, locked, asleep → wake; notifications denied → enabled; DST and a time-zone switch; corrupt-file recovery for each store |
| **G2-agent** | Every matrix row: hold, release within 1 s, 60 s expiry, Open per host, no double resume, setup round trip |
| **G3 Input** | The §6 corpus gates |
| **G4 Access & design** | Keyboard-only and VoiceOver runs of J1–J4; founder sign-off of 5 screens against the mockups in both themes; design re-review ≥7/10; voice check passes |
| **G5 Ship** | Clean install from the downloaded DMG passes Gatekeeper; an update 0.9.0 → 0.9.1 keeps the data; uninstall restores configs byte-identically; release CI is green |

### Journeys

| ID | Journey | What happens |
|---|---|---|
| J1 | First ten minutes, developer | Wave → set a real reminder → notifications and login → connect Claude Code → live first event → the reminder fires |
| J2 | First ten minutes, no agents | Steps 1–2, then Skip; no developer word appears anywhere |
| J3 | Needs you | Session waiting in another tab → Pip "!" + one chime → card shows project, first prompt line and the full command → Allow once, or Open (lands on the tab and releases the hold); keyboard path works |
| J4 | Reminder lifecycle | "dentist thu 2:30" → preview → Enter → Undo shown; it fires; Snooze 1 h; a weekly reminder snoozed to Tuesday stays on Mondays; sleep through a reminder → "While you were away" on wake |
| J5 | Log and read back | "note for evaluation: …" → asks which notebook → saved with Move; a session finishes → Log it; Friday → Your week → Copy |
| J6 | Come back | v1.1 |
| J7 | Uninstall | Disconnect & uninstall → hooks removed and checked → data kept or deleted → Claude Code behaves as before |

### Private beta (needs G1–G5)

- **Wave 1:** 8 developers who use Claude Code daily, plus 3 people with no agents, for 2 weeks
  with the updater live.
- **Wave 2:** 20 people for 2 weeks, only if wave 1 had zero trust incidents.

**Measurement.** No telemetry. An opt-in "Copy weekly summary" contains counts only:
- reminders fired and acknowledged on time;
- log entries kept;
- requests answered on Pip vs released;
- Open successes and misses (one-tap thumbs-down);
- Quick add misses;
- hides and quits, each with a one-tap reason.

Interviews on day 7 and day 14.

**Targets** (wave 1, measured on day 14):

| Measure | Target |
|---|---|
| Developers activated on day 1 | ≥6/8 |
| Developers using it ≥3 days in week 2 | ≥5/8 |
| Open success rate | ≥95% |
| Testers keeping ≥3 log entries a week | ≥4 of 11 |
| Trust incidents (wrong-session approval, lost note, missed supported reminder) | **0** |

**Rules:**
- Any trust incident freezes the beta until a fix ships with a regression test.
- **Continue** to public v1: all targets met, and G1–G5 still pass on the release build.
- **Switch the promise to the core track:** developers release most requests to the terminal but
  keep reminders and the log.
- **Switch to the everyday direction:** testers with no agents retain better than developers.
- **Stop feature work and rethink:** fewer than half of all testers are active on day 14.

## 13. Guardrails for the agents building this

1. **This file is the only contract.** PLAN-V2 §6–10 and ROADMAP point here.
2. **Additions:** one in, one out. Each needs:
   - a dated DECISIONS entry that names what it displaces;
   - a 24-hour wait;
   - the founder's yes.

   "The user asked" means *write it down*, not build it that hour.
3. **Work in progress = 1.**
   - "Done" means tests plus a dated founder hand-check line with a build hash in `docs/checks/`.
   - Agents never mark anything done.
   - At most 2 verifiable items a day for the founder.
4. **CI:**
   - typecheck, vitest, cargo test, `clippy -D warnings`;
   - the WebKit check (it can't be skipped);
   - the corpus;
   - the voice check.
5. **Second review.** Changes to `hooks.rs`, `requests.rs`, the sidecar, installers, uninstall or
   `store.rs` need a review by a second agent (Claude ↔ Codex), with adversarial cases.
6. **No new dependency, permission or entitlement** without a DECISIONS line. Cutting a feature
   deletes its code. Commits stay under about 600 net added lines.
7. **Art and pipelines are frozen.** Nothing staged goes in without an item ID from this file.
8. **No claim without a matrix row.**
   - No UI text, sample data or preview may show a capability that has no matrix row.
   - README and GUIDE change in the same commit as the behaviour.
9. **STATUS.md** is rewritten at each handoff and stays ≤150 lines. History goes to
   `memory/LOG.md`.
10. **Global agent configs:** never touched by agents (AGENTS.md). Use temporary config dirs.
